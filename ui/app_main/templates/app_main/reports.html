Как устроена оценка

Цепочка задаёт предсказываемые этапы: response получает эталонные состояние и действие; policy → response — эталонное состояние; полная цепочка предсказывает состояние, действие и ответ.

Контекст задаёт предысторию между ходами: эталонную из датасета или собственную память и ответы модели. Сообщения пользователя можно брать из датасета либо получать от симулятора, который реагирует на действия модели.

Собственная предыстория поддерживается для полной цепочки; симулятор требует собственную предысторию. Пользователь всегда пишет первым. В модульной цепочке этапы используют отдельные checkpoints; в UBAR — один. History — прямой ответ по истории.

python benchmark.py --model runs/ubar --split validation --chain full --context reference --user-source dataset --output runs/eval-ubar
